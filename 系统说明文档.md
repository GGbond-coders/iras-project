## 1. 系统概述

### 1.1 系统目标

IRAS 是一个集 **用户管理**、**本地职位库检索**、**AI 简历智能分析** 于一体的现代化招聘辅助平台。系统采用前后端分离架构，通过对接 Dify 大模型工作流，实现非结构化简历到结构化诊断报告的智能转化。

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| 用户认证 | 基于 Spring Security + JWT 的无状态会话管理 |
| 职位检索 | 基于 MySQL 的多字段模糊匹配与分页展示 |
| 职能画像 | 输入职位名称 → Dify AI 生成硬技能、软技能、工具、经验要求 |
| 智能诊断 | 上传简历文件 → Dify AI 匹配岗位并生成匹配分、差距分析、面试建议 |

### 1.3 角色权限

- **普通求职者**：注册/登录、检索职位、上传简历、获取 AI 诊断报告

## 3. 功能模块详解

### 3.1 用户认证模块

- **注册**：用户名 + 密码（可选邮箱），密码 BCrypt 加密存储
- **登录**：支持用户名或邮箱登录，返回 JWT Token
- **鉴权**：Spring Security 拦截器 + JWT 过滤器，无状态会话管理
- **Token 有效期**：24 小时

### 3.2 职位检索模块

- **搜索字段**：职位名称、工作地点、薪资范围（最低/最高）
- **匹配方式**：模糊匹配（LIKE）、动态 SQL 条件拼接
- **分页**：每页 20 条，支持切换 20/50/100
- **排序**：按 ID 倒序

### 3.3 职能画像模块

- **输入**：职位名称（文本）
- **处理**：转发至 Dify Workflow API
- **输出**：结构化 JSON，包含：
  - `job_title`：职位名称
  - `hard_skills`：硬技能列表
  - `soft_skills`：软技能列表
  - `tools`：常用工具列表
  - `experience`：经验要求
  - `education`：学历要求
- **推理时间**：约 2 分钟

### 3.4 智能诊断模块

- **输入**：简历文件（.txt / .text / .pdf / .doc / .docx）
- **处理流程**：
  1. 前端上传文件 → 后端接收 `MultipartFile`
  2. 后端上传文件到 Dify `/files/upload`，获取 `upload_file_id`
  3. 用 `upload_file_id` 调用 Dify Workflow API
  4. 返回结构化诊断结果
- **输出**：JSON 数组，每个元素包含：
  - `matched_score`：匹配分（0-100）
  - `matched_job`：匹配岗位名称
  - `type` / `company` / `city` / `salary`：岗位信息
  - `matched_reason`：匹配原因
  - `gap_points`：差距分析列表
  - `interview_advice`：面试建议列表
- **推理时间**：约 3 分钟
- **`<think>` 标签**：AI 推理过程默认隐藏，通过按钮切换展示

```sql
-- 用户表
CREATE TABLE `user` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `username` varchar(50) NOT NULL COMMENT '用户名',
  `password` varchar(255) NOT NULL COMMENT 'BCrypt加密密码',
  `email` varchar(100) DEFAULT NULL COMMENT '联系邮箱',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户系统表';

-- 职位库表
CREATE TABLE `job_info` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `job_name` varchar(100) NOT NULL COMMENT '职位名称',
  `company_name` varchar(100) NOT NULL COMMENT '公司名称',
  `city` varchar(50) DEFAULT NULL COMMENT '城市',
  `salary` varchar(50) DEFAULT NULL COMMENT '薪资范围',
  `jd_text` text NOT NULL COMMENT '职位详情(JD内容)',
  `type` varchar(50) DEFAULT NULL COMMENT '职位分类',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP,
  `update_time` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_job_name` (`job_name`),
  KEY `idx_city` (`city`),
  FULLTEXT KEY `idx_fulltext_jd` (`jd_text`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='职位库表';
```

### 5.3 安全认证模块

#### SecurityConfig.java — Spring Security 核心配置

```java
@Configuration
@EnableWebSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtAuthenticationFilter;
    private final ObjectMapper objectMapper;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(AbstractHttpConfigurer::disable)              // 1. 禁用 CSRF（前后端分离不需要）
            .cors(cors -> cors.configurationSource(corsConfigurationSource()))  // 2. 启用 CORS
            .sessionManagement(session -> 
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))  // 3. 无状态会话
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll()    // 4. 认证接口放行
                .requestMatchers(HttpMethod.OPTIONS, "/**").permitAll()  // 5. OPTIONS 预检放行
                .anyRequest().authenticated()                   // 6. 其他接口需认证
            )
            .exceptionHandling(ex -> ex
                .authenticationEntryPoint((request, response, authException) -> {
                    response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
                    response.setContentType(MediaType.APPLICATION_JSON_VALUE);
                    objectMapper.writeValue(response.getWriter(), 
                        Result.error(401, "未登录或Token已过期"));
                })                                              // 7. 未认证返回 401 JSON
            )
            .addFilterBefore(jwtAuthenticationFilter, 
                UsernamePasswordAuthenticationFilter.class);    // 8. JWT 过滤器在认证过滤器之前
        return http.build();
    }
}
```

**配置要点解析：**

1. **禁用 CSRF**：前后端分离架构中，前端通过 JWT Token 认证，不依赖 Cookie，因此 CSRF 防护无意义
2. **CORS 配置**：允许所有来源（开发环境），生产环境应限制为具体域名
3. **无状态会话**：Spring Security 不创建 HttpSession，每次请求都通过 JWT 验证身份
4. **过滤器链顺序**：`JwtAuthenticationFilter` → `UsernamePasswordAuthenticationFilter` → Controller

#### JwtAuthenticationFilter.java — JWT 认证过滤器

```java
@Component
@RequiredArgsConstructor
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    private final JwtUtil jwtUtil;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        // 1. 从请求头提取 Token
        String token = extractToken(request);

        // 2. 验证 Token 有效性
        if (StringUtils.hasText(token) && jwtUtil.validateToken(token)) {
            // 3. 从 Token 中解析用户名
            String username = jwtUtil.getUsernameFromToken(token);
            // 4. 创建认证对象并放入 SecurityContext
            UsernamePasswordAuthenticationToken authentication =
                    new UsernamePasswordAuthenticationToken(username, null, Collections.emptyList());
            SecurityContextHolder.getContext().setAuthentication(authentication);
        }

        // 5. 继续过滤器链
        filterChain.doFilter(request, response);
    }

    private String extractToken(HttpServletRequest request) {
        String bearerToken = request.getHeader("Authorization");
        if (StringUtils.hasText(bearerToken) && bearerToken.startsWith("Bearer ")) {
            return bearerToken.substring(7);  // 去掉 "Bearer " 前缀
        }
        return null;
    }
}
```

**执行流程：**

```
请求进入 → extractToken() 提取 Bearer Token
         → validateToken() 验证签名和有效期
         → getUsernameFromToken() 解析用户名
         → 创建 Authentication 对象
         → 存入 SecurityContextHolder
         → 后续 Controller 可通过 @AuthenticationPrincipal 获取用户名
```

#### JwtUtil.java — JWT 工具类

```java
@Component
public class JwtUtil {

    @Value("${jwt.secret}")
    private String secret;

    @Value("${jwt.expiration}")
    private long expiration;

    private SecretKey getSigningKey() {
        // 使用 HMAC-SHA 算法生成签名密钥
        return Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
    }

    public String generateToken(String username) {
        return Jwts.builder()
                .subject(username)                              // 设置主题（用户名）
                .issuedAt(new Date())                           // 签发时间
                .expiration(new Date(System.currentTimeMillis() + expiration))  // 过期时间
                .signWith(getSigningKey())                      // 签名
                .compact();                                     // 生成字符串
    }

    public String getUsernameFromToken(String token) {
        return Jwts.parser()
                .verifyWith(getSigningKey())                    // 验证签名
                .build()
                .parseSignedClaims(token)                       // 解析 Claims
                .getPayload()
                .getSubject();                                  // 获取用户名
    }

    public boolean validateToken(String token) {
        try {
            Jwts.parser()
                .verifyWith(getSigningKey())
                .build()
                .parseSignedClaims(token);
            return true;
        } catch (JwtException | IllegalArgumentException e) {
            return false;  // Token 无效或已过期
        }
    }
}
```

**JWT Token 结构：**

```
Header.Payload.Signature

Header:    {"alg": "HS512", "typ": "JWT"}
Payload:   {"sub": "username", "iat": 1714464000, "exp": 1714550400}
Signature: HMAC-SHA512(header + "." + payload, secret)
```

#### AuthServiceImpl.java — 注册/登录核心逻辑

```java
@Service
@RequiredArgsConstructor
public class AuthServiceImpl implements AuthService {

    private final UserMapper userMapper;
    private final PasswordEncoder passwordEncoder;   // BCrypt 编码器
    private final JwtUtil jwtUtil;

    @Override
    public Result<Map<String, Object>> register(RegisterRequest request) {
        // 1. 检查用户名唯一性
        if (userMapper.findByUsername(request.getUsername()) != null) {
            return Result.error(400, "用户名已存在");
        }
        // 2. 检查邮箱唯一性
        if (request.getEmail() != null && userMapper.findByEmail(request.getEmail()) != null) {
            return Result.error(400, "邮箱已被注册");
        }
        // 3. 密码 BCrypt 加密
        User user = new User();
        user.setUsername(request.getUsername());
        user.setPassword(passwordEncoder.encode(request.getPassword()));
        user.setEmail(request.getEmail());
        userMapper.insert(user);
        // 4. 生成 JWT Token 并返回
        String token = jwtUtil.generateToken(user.getUsername());
        Map<String, Object> data = new HashMap<>();
        data.put("token", token);
        data.put("username", user.getUsername());
        data.put("email", user.getEmail());
        return Result.success("注册成功", data);
    }

    @Override
    public Result<Map<String, Object>> login(LoginRequest request) {
        // 1. 支持用户名或邮箱登录
        User user = userMapper.findByUsername(request.getUsername());
        if (user == null) {
            user = userMapper.findByEmail(request.getUsername());
        }
        if (user == null) {
            return Result.error(401, "用户名或密码错误");
        }
        // 2. BCrypt 密码验证
        if (!passwordEncoder.matches(request.getPassword(), user.getPassword())) {
            return Result.error(401, "用户名或密码错误");
        }
        // 3. 生成 Token
        String token = jwtUtil.generateToken(user.getUsername());
        Map<String, Object> data = new HashMap<>();
        data.put("token", token);
        data.put("username", user.getUsername());
        data.put("email", user.getEmail());
        return Result.success("登录成功", data);
    }
}
```

**安全设计要点：**
- 密码使用 **BCrypt** 加密，每次加密结果不同（含随机盐），无法逆向破解
- 登录失败统一返回 "用户名或密码错误"，不泄露具体是哪个字段错误
- 注册成功/登录成功后立即返回 Token，前端无需再次登录

### 5.5 职位检索模块

#### JobMapper.xml — 动态 SQL

```xml
<select id="searchJobs" resultType="com.iras.entity.JobInfo">
    SELECT * FROM job_info
    <where>
        <if test="jobName != null and jobName != ''">
            AND job_name LIKE CONCAT('%', #{jobName}, '%')
        </if>
        <if test="city != null and city != ''">
            AND city LIKE CONCAT('%', #{city}, '%')
        </if>
        <if test="salaryMin != null and salaryMin != ''">
            AND CAST(REPLACE(REPLACE(salary, 'k', ''), 'K', '') AS UNSIGNED) &gt;= #{salaryMin}
        </if>
        <if test="salaryMax != null and salaryMax != ''">
            AND CAST(REPLACE(REPLACE(salary, 'k', ''), 'K', '') AS UNSIGNED) &lt;= #{salaryMax}
        </if>
    </where>
    ORDER BY id DESC
    LIMIT #{offset}, #{size}
</select>
```

**SQL 解析：**

- `<where>` 标签：自动去除多余的 `AND` / `OR` 前缀
- `<if>` 标签：条件不为空时才拼接 SQL，实现动态查询
- `LIKE CONCAT('%', #{jobName}, '%')`：模糊匹配，`#{}` 防止 SQL 注入
- `CAST(REPLACE(...) AS UNSIGNED)`：将薪资字符串（如 "15000"）转为数字进行范围比较
- `LIMIT #{offset}, #{size}`：分页查询，offset = (page - 1) * size

#### JobServiceImpl.java — 分页逻辑

```java
@Service
@RequiredArgsConstructor
public class JobServiceImpl implements JobService {

    private final JobMapper jobMapper;

    @Override
    public PageResult<JobInfo> searchJobs(JobSearchRequest request) {
        int page = request.getPage() != null ? request.getPage() : 1;
        int size = request.getSize() != null ? request.getSize() : 20;
        int offset = (page - 1) * size;

        // 查询当前页数据
        List<JobInfo> records = jobMapper.searchJobs(
                request.getJobName(), request.getCity(),
                request.getSalaryMin(), request.getSalaryMax(),
                offset, size);

        // 查询总记录数
        long total = jobMapper.countSearchJobs(
                request.getJobName(), request.getCity(),
                request.getSalaryMin(), request.getSalaryMax());

        // 封装分页结果
        PageResult<JobInfo> result = new PageResult<>();
        result.setRecords(records);
        result.setTotal(total);
        result.setPage(page);
        result.setSize(size);
        result.setTotalPages((int) Math.ceil((double) total / size));
        return result;
    }
}
```

```java
    private String uploadFile(MultipartFile file) {
        String boundary = "----WebKitFormBoundary" + System.currentTimeMillis();
        String uploadUrl = baseUrl + "/files/upload";

        HttpURLConnection connection = (HttpURLConnection) new URL(uploadUrl).openConnection();
        connection.setRequestMethod("POST");
        connection.setRequestProperty("Authorization", "Bearer " + resumeDiagnosisKey);
        connection.setRequestProperty("Content-Type", "multipart/form-data; boundary=" + boundary);
        connection.setDoOutput(true);

        try (OutputStream os = connection.getOutputStream()) {
            // 写入文件字段
            os.write(("--" + boundary + "\r\n").getBytes());
            os.write(("Content-Disposition: form-data; name=\"file\"; filename=\"" +
                    file.getOriginalFilename() + "\"\r\n").getBytes());
            os.write(("Content-Type: " + file.getContentType() + "\r\n\r\n").getBytes());
            os.write(file.getBytes());
            os.write("\r\n".getBytes());

            // 写入 user 字段（Dify 要求）
            os.write(("--" + boundary + "\r\n").getBytes());
            os.write("Content-Disposition: form-data; name=\"user\"\r\n\r\n".getBytes());
            os.write("iras-user\r\n".getBytes());

            os.write(("--" + boundary + "--\r\n").getBytes());
        }

        // 解析响应，提取文件 ID
        JsonNode root = objectMapper.readTree(connection.getInputStream());
        return root.get("id").asText();  // 返回 upload_file_id
    }
```

```java
        HttpURLConnection connection = (HttpURLConnection) new URL(urlStr).openConnection();
        connection.setRequestMethod("POST");
        connection.setRequestProperty("Authorization", "Bearer " + apiKey);
        connection.setRequestProperty("Content-Type", "application/json");
        connection.setDoOutput(true);
        connection.setConnectTimeout(300000);  // 5 分钟超时（AI 推理慢）
        connection.setReadTimeout(300000);

        try (OutputStream os = connection.getOutputStream()) {
            os.write(requestBody.getBytes(StandardCharsets.UTF_8));
        }

        int responseCode = connection.getResponseCode();
        String responseBody = new String(
            connection.getInputStream().readAllBytes(), StandardCharsets.UTF_8);

        // 解析 Dify 响应，提取 outputs.result
        JsonNode root = objectMapper.readTree(responseBody);
        JsonNode outputs = root.path("data").path("outputs");
        if (outputs.has("result")) {
            return outputs.get("result").asText();
        }
        return responseBody;
    }
```

```javascript
  // 从 localStorage 恢复状态（页面刷新后保持登录）

  const username = ref(localStorage.getItem('username') || '')

  function setUser(userData) {

    username.value = ''
    email.value = ''

    localStorage.removeItem('username')
    localStorage.removeItem('email')
  }
```

```javascript
  const res = await difyApi.diagnoseResume(selectedFile.value)
  let data = res.data

  // 提取 <think> 标签内容（AI 推理过程）
  const thinkMatch = data.match(/<think>([\s\S]*?)<\/think>/)
  if (thinkMatch) {
    thinkContent.value = thinkMatch[1].trim()       // 保存推理过程
    data = data.replace(/<think>[\s\S]*?<\/think>/, '').trim()  // 移除推理标签
  }

  // 解析 JSON 结果
  try {
    const parsed = JSON.parse(data)
    if (Array.isArray(parsed)) {
      matches.value = parsed              // 直接是数组
    } else if (parsed.matches) {
      matches.value = parsed.matches      // 包含 matches 字段
    } else if (parsed.result) {
      // 嵌套 result 字段（Dify 可能返回嵌套结构）
      const inner = parsed.result
      const innerThink = inner.match(/<think>([\s\S]*?)<\/think>/)
      if (innerThink) thinkContent.value = innerThink[1].trim()
      const cleanJson = inner.replace(/<think>[\s\S]*?<\/think>/, '').trim()
      const innerParsed = JSON.parse(cleanJson)
      matches.value = Array.isArray(innerParsed) ? innerParsed : [innerParsed]
    }
  } catch {
    rawResult.value = data    // 非 JSON，作为 Markdown 渲染
  }
}
```

## 9. 常见问题

### Q1: Dify API 调用超时？
A: Dify AI 推理时间约 2-3 分钟，后端已设置 5 分钟超时。如果仍然超时，检查网络连接或增加 `connection.setReadTimeout()` 值。

### Q2: 页面刷新后登录状态丢失？
A: 不会。Token 存储在 `localStorage` 中，Pinia Store 在初始化时会从 `localStorage` 恢复。

### Q3: 如何添加更多职位数据？
A: 直接向 `job_info` 表插入数据：
```sql
INSERT INTO job_info (job_name, company_name, city, salary, jd_text, type)
VALUES ('Python开发', '某公司', '北京', '20000', '职位描述...', '全职');
```

### Q4: 如何更换 Dify API Key？
A: 修改 `backend/src/main/resources/application.yml` 中的 `dify.job-profile-key` 和 `dify.resume-diagnosis-key`。

### Q5: 前端页面缓存不生效？
A: 确认 Layout.vue 中使用了 `<keep-alive>` 包裹 `<router-view>`。被缓存的组件会调用 `onDeactivated` 生命周期钩子，而非 `onUnmounted`。
